# Hostidian

Self-hosted, multi-user, real-time collaborative notes — a Notion-style editor with Obsidian-style `[[links]]`, backlinks and graph, installable on your phone as an offline-capable PWA.

- **Automatic sync** between all your devices (the server is the source of truth; edits merge via Yjs CRDTs, even offline).
- **Users & access:** multiple users and workspaces per instance, page-level sharing, guests, public share links, comments.
- **MCP:** let your AI agents (Claude Code, Cursor, …) read and edit pages as you, with scoped, revocable access tokens — see [docs/mcp.md](docs/mcp.md).
- **Docker-first:** `docker compose up` brings up Postgres, the Go API, the collaboration server, the Next.js web app and Caddy (automatic HTTPS).
- **Open source:** AGPL-3.0.

> Status: under construction. See [`docs/plan.md`](docs/plan.md) for the roadmap and [`docs/architecture.md`](docs/architecture.md) for how it fits together.

## Quick start

Requires Docker with the Compose v2 plugin.

```bash
git clone https://github.com/UlugbekMuslitdinov/hostidian.git
cd hostidian
./scripts/gen-env.sh      # creates .env with random secrets (asks for the domain; default: localhost)
docker compose up -d      # builds and starts everything; first run takes a few minutes
```

Open <https://localhost> (accept the self-signed certificate), create the administrator account on the setup screen, then create a workspace and invite people. `make up` does the same in one step.

For a real server, run `./scripts/gen-env.sh --domain notes.example.com` instead: Caddy then obtains and renews a Let's Encrypt certificate automatically (DNS must point at the host and ports 80/443 must be reachable). Plain HTTP for a LAN: `--domain http://notes.lan`.

> The PWA (offline mode, "Add to Home Screen") needs HTTPS with a trusted certificate, or `http://localhost`. For phones use a real domain, [Tailscale or a Cloudflare Tunnel](docs/deployment.md#installing-the-pwa-on-a-phone).

## Configuration

Everything is configured through `.env` (template: [`.env.example`](.env.example)):

| Variable | Purpose |
|---|---|
| `DOMAIN`, `PUBLIC_URL` | Site address served by Caddy and the externally visible URL (must match what users open). |
| `ALLOWED_ORIGINS` | Extra browser origins allowed besides `PUBLIC_URL`. |
| `HTTP_PORT`, `HTTPS_PORT` | Published ports (default 80 and 443). |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `DATABASE_URL` | Database credentials and connection string. |
| `COLLAB_JWT_SECRET`, `INTERNAL_TOKEN`, `APP_SECRET` | Random secrets generated by `gen-env.sh`. |
| `API_ADDR`, `INTERNAL_ADDR`, `COLLAB_INTERNAL_URL`, `COLLAB_PUBLIC_URL`, `DATA_DIR`, `MAX_UPLOAD_MB`, `MAX_IMPORT_MB`, `LOG_LEVEL` | Go API settings. |
| `COLLAB_PORT`, `COLLAB_INTERNAL_PORT`, `API_INTERNAL_URL` | Collaboration server settings. |
| `OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_NAME` | Optional single sign-on. Redirect URI to register: `${PUBLIC_URL}/api/auth/oidc/callback`. |

Every variable, with defaults and which service uses it, is documented in [docs/deployment.md](docs/deployment.md#configuration).

**Deploying on Coolify?** Use `docker-compose.coolify.yml`, not `docker-compose.yml`: [docs/deployment.md#coolify](docs/deployment.md#coolify).

## Operations

| Task | Command |
|---|---|
| Start / stop | `make up` / `make down` (or `docker compose up -d` / `docker compose down`) |
| Status and logs | `make ps`, `make logs` (`make logs SERVICE=api`) |
| Back up database and files | `make backup` (writes to `./backups`) |
| Restore | `make restore DB=backups/hostidian-<ts>.sql.gz FILES=backups/hostidian-files-<ts>.tar.gz` |
| Upgrade | `make backup && git pull && docker compose up -d --build` |

Only Caddy publishes ports (80, 443, 443/udp). Postgres and the internal API ports never leave the Docker network, and Caddy returns 404 for every `/internal*` path. More in [docs/deployment.md](docs/deployment.md): HTTPS and domains, running behind Traefik or nginx (WebSocket and SSE requirements), Tailscale and Cloudflare Tunnel, OIDC providers (Authentik, Keycloak, Google), backups, upgrades, security notes and troubleshooting.

## Development

Prerequisites: Go 1.26, Node 22.12+, pnpm 9.10 (via Corepack), Docker.

```bash
pnpm install                 # or: scripts/pnpm.sh install
make dev-db                  # Postgres on 127.0.0.1:5432
make dev-api                 # Go API on :8080 / :8081          (terminal 1)
make dev-collab              # collab server on :1234 / :1235   (terminal 2)
make dev-web                 # Next.js on :3000                 (terminal 3)
make dev-proxy               # optional: single origin at http://localhost:8000, like production
```

Day-to-day targets (`make help` lists all of them):

| Target | What it does |
|---|---|
| `make gen` | Regenerate TypeScript API types and Go code (sqlc, oapi-codegen) from `api/openapi.yaml` and the SQL files. |
| `make lint` | gofmt, `go vet`, TypeScript checks, ESLint, OpenAPI lint. |
| `make test` | Go unit and integration tests (testcontainers, needs Docker) and the Vitest suites. |
| `make build` | Compile the API binary and build collab and web. |
| `make images` | Build the three Docker images. |

CI (`.github/workflows/ci.yml`) runs the same checks plus image builds on every pull request; pushing a `v*` tag publishes multi-arch images to GHCR and creates a GitHub release.
